# @nodrail/cli

Nodrail is the open control plane for AI agent development. This is its
command line. Your repository holds the desired state: `nodrail.yaml`, the
rules files it imports and `nodrail.lock.yaml`. `nodrail plan` shows what
would change on each agent host (Claude Code, Codex, Copilot), and
`nodrail apply` sets it up: the agents, their skills and connections, and a
hook that allows or denies every action before it runs.

```sh
nodrail example support-desk ./desk
nodrail plan ./desk --runtime claude-code
nodrail apply ./desk --runtime claude-code
```

Requires Node.js 22 or later and Claude Code. Follow
[Get started](https://nodrail.com/docs/get-started#install) to install the published
CLI. On macOS or Linux you can also select
`--runtime codex` or `--runtime copilot`.
On Windows, `PATH` can point to a directory containing the Claude Code
`.cmd` launcher. Windows system directories can be omitted from that `PATH`.

A rule only allows or denies. Gates, budgets and evidence say when a call is
allowed; until they are met, the call is denied with what is missing, so the
agent fixes it and tries again. Nothing waits for a person, and what can't be
undone (a production deploy, a merge to main, deleting data) stays with
people, outside the agents.

## Connect a control plane

Run `nodrail connect <url> --workspace <slug> --environment <slug>` in the
project folder. It sets the destination and project ID, signs in through the
browser if needed, updates the lock for the connection change and shows the plan. If the project has unlocked edits, run `nodrail policy lock` to review them before connecting. Review the plan before
running `nodrail apply`. Apply publishes policy changes, enrolls this machine
and installs the engine hook on Claude Code, Codex or Copilot. The hook
verifies the policy against the lock and decides on the host. Use the console's
generated check command and its Activity link to find the first decision by its
check token. For Claude Code, `plan --require-active` checks that the current
enforcement hook is configured in settings. The matching first-check decision
in Activity confirms that the hook ran and reported. Open **Activity → Runs** to review decisions by run.

`plan` reports hook activation and a pending policy revision separately. Read
the machine setup total in the same units in `plan` and `apply`.

If the control plane is unreachable, the hook uses its last verified
copy when the digest matches the lock. Without a matching copy, enforcement
mode denies the call with a reason. Watch mode records policy verdicts and
evaluation failures while leaving ordinary calls to the host's permissions.
The setup guard stays active in watch mode.

Use `decide: local` for repository policy with a local record in watch
mode. See [Connect to Nodrail](docs/playbooks.md#connect-to-nodrail) for the
manual manifest setup, automatic machine enrollment and CI configuration.

## A project's policy (offline, no account)

A repository describes its policy in `nodrail.yaml`: catalog modules and its
own rules files, in the order they apply. The catalog ships inside this
package, so nothing is downloaded.

```sh
nodrail add @nodrail/open-reviewed-pr   # or its other name, @nodrail/pr_policy.yaml
# Give the module your repository in nodrail.yaml:
#   with: { repository: acme/widgets }
nodrail policy lock                     # shows who gains or loses what, records it
nodrail policy export --frozen > effective.yaml
```

Commit `nodrail.yaml` and `nodrail.lock.yaml` together with the project sources
they reference. The support-desk example includes a `.gitignore` for host
files and machine state generated by apply. The lock records the
exact version and file hashes of every module and file, and the reviewed
policy. `policy export --frozen` checks all of it, offline, and prints one
ordinary policy file only when everything matches. In CI, export to a
temporary file and replace the deployed one only on success: a shell redirect
empties the old file before nodrail runs.

The catalog:

| Module                        | Needs        | What it lets an agent do                                                                                                                                                                                            |
| ----------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@nodrail/read-only`          | nothing      | Every agent reads, searches and runs commands that only look; credentials stay out of reach. The `read-only` starter pack.                                                                                          |
| `@nodrail/open-reviewed-pr`   | `repository` | `github` opens draft pull requests after QA, checks and review pass on the current candidate. Never merges or starts its own checkers.                                                                              |
| `@nodrail/merge-reviewed-pr`  | `repository` | `merger` merges only after QA, checks and review pass on the head. Never pushes, changes files, uses the shell or starts its own checkers.                                                                          |
| `@nodrail/triage-issues`      | `repository` | `triage` reads, comments on and labels issues. Changes nothing else and uses no shell.                                                                                                                              |
| `@nodrail/dependency-updates` | `repository` | `deps` writes lockfiles (matched by file name), refreshes them with scripts off, commits and pushes its own branch. Never changes package.json, pushes to main or force-pushes. Opens a draft once the checks pass. |

File and command rules apply wherever the Claude Code hook runs. GitHub rules
(`tool: github`, operations such as `pr.open` and `issues.comment` on a
`repository`) take effect only where an adapter maps GitHub calls to those
names and supplies the run's evidence; their guarantee covers the calls that
adapter mediates. Adding a module installs no hook and runs nothing; agents
follow a policy once you activate an export for them.

## Policies (offline, no account)

`nodrail policy` is
[`nodrail-policy`](https://www.npmjs.com/package/@nodrail/policy-engine), the
policy engine's command: the same commands, flags, output and exit codes,
with no token and nothing sent anywhere.

```sh
nodrail policy init repo-work > rules.yaml
nodrail policy validate rules.yaml
nodrail policy eval rules.yaml --command 'git status'
nodrail policy check rules.yaml -- git status
nodrail policy --help               # every command and flag
```

For `nodrail policy test rules.yaml --cases cases.yaml`, use both files from
[Policies](https://nodrail.com/docs/policies), then run the command from their folder.

Hooks and plugins that already run `nodrail-policy` keep working; both
answer Claude Code byte for byte alike.

## Your control plane

The control plane is the open Nodrail server, self-hosted or Nodrail Cloud. It
keeps the published policy, runs, receipts, decisions, shared budgets and
evidence. With a personal API token, the command uses its management API to
read your workspace's Activity, runs and Insights, and to pull or publish its
rules file.

> **Never give a token that can publish to an agent Nodrail governs.** One
> holding `rules:write` could rewrite the rules that hold it back. Agents and
> assistants get `read` tokens.

### Log in

Run `nodrail login` for Nodrail Cloud or give your server's address. Confirm
the sign-in in the browser using your console account.

```sh
nodrail login --url https://nodrail.example.com
nodrail whoami
nodrail logout
```

Bare commands use the last signed-in server outside a project. The project's
`connect:` selects its workspace and environment. Use `--workspace <slug>` for
management commands outside a project if you belong to multiple workspaces.

For automation, use a personal API token from **your account → API tokens**.
Pipe an `ndp_` token to `nodrail login --token-stdin` or set `NODRAIL_TOKEN`
and `NODRAIL_URL`. Publishing needs `rules:write`. A supplied token travels
only to its configured server, over HTTPS or loopback HTTP.

The CLI saves login credentials in `~/.nodrail/cli.json`. It protects sessions,
machine credentials, and pending enrollment records with per-user DPAPI on
Windows and with `0600` files in `0700` directories on POSIX. Older files are
upgraded when read. On Windows, the CLI and hook must run under the account
that saved the credential.
`nodrail logout` revokes a browser CLI session. Personal API tokens can be
revoked in the console.

After connecting a project, run `nodrail policy lock`, `nodrail plan`, then
`nodrail apply`. Select `--runtime` if the project declares multiple runtimes.
Connected apply registers agents and publishes both the policy and intended
revision. It stores this machine's project credential outside the repository
under `~/.nodrail/hosts/`. Use a policy manager or admin account for a first
apply or a change to the published lock.

### Activity, runs and Insights

```sh
nodrail activity --outcome denied --range 24h
nodrail activity --q acme/app --kind decisions --json
nodrail runs --agent dev-bot
nodrail run 7e2d3a1b-…
nodrail insights --days 7
```

`activity` takes the Activity page's filters: `--q`, `--agent`, `--outcome`
(`allowed`, `denied`), `--kind` (`decisions`, `reports`, `changes`),
`--range` (`24h`, `7d`, `30d`) and `--run`. Lists show 50 items; `--limit`
(up to 100) and `--cursor` page through more.

### Rules

```sh
nodrail rules pull rules.yaml       # or to stdout without a file
nodrail rules push rules.yaml
```

`nodrail destroy` removes generated host setup and disconnects the machine enrolled by `nodrail apply`. Published policy, history, the manifest's `connect:` block, and your login stay. Use `nodrail logout --url <url>` to end your CLI session. If apply stopped before recording its result, destroy uses your personal sign-in to reconcile that generation. When the server cannot confirm the result, destroy keeps the local record and exits with code 1 so you can retry. For older enrollments whose generated connection file was lost or edited, restore the original file and credential before running `nodrail destroy --yes`, or revoke the machine in the console.

`push` needs a token with `rules:write`. It previews the file, shows the
difference from the active rules and what would be added, changed or removed,
asks, and publishes exactly what it previewed. If someone changed the rules in
between, it refuses: pull again, merge, and push again.

### Project hook and standalone plugin

For Claude Code, `apply` records the installed project hook in the user's private Nodrail directory. The standalone plugin steps aside when the installed files still match. Start a new Claude Code session after apply to load its settings. A credential explicitly referenced by `connect.credential` needs `NODRAIL_URL` set to the issuing origin.

## Options

| Option                 | Meaning                                                             |
| ---------------------- | ------------------------------------------------------------------- |
| `--json`               | Machine-readable output on stdout; notes and questions go to stderr |
| `-e`, `--environment`  | An environment's slug; the workspace's default otherwise            |
| `--url`, `NODRAIL_URL` | Nodrail's address, for self-hosting                                 |
| `-y`, `--yes`          | Don't ask before publishing                                         |

Exit codes: `0` done, `1` failed (the error's code and request ID are
printed), `2` the command line was wrong.

## Library

`@nodrail/cli/api` is the typed client the command uses:

```ts
import { NodrailApi } from "@nodrail/cli/api";

const api = new NodrailApi({ token: process.env.NODRAIL_TOKEN! });
const { items } = await api.runs();
```

The management API is documented at
[nodrail.com/docs/api](https://nodrail.com/docs/api).

## Connected Inventory

Enrollment and telemetry share `~/.nodrail/machine-id`. Upgrading keeps an
existing legacy hex or UUID file intact. If the CLI reports an invalid machine
ID, remove the damaged file with `rm ~/.nodrail/machine-id` (PowerShell:
`Remove-Item ~/.nodrail/machine-id`) and run `nodrail apply` again.

Connected projects send host observations to the enrolled environment using their machine credential. `nodrail apply` sends the first setup report. Session-start observation and `nodrail observe` refresh activation, revision and count data. Use `observe: { names: true }` to include names. Optional OTLP export can use a separate `NODRAIL_INVENTORY_TOKEN` when sending to the legacy Nodrail OTLP endpoint.
